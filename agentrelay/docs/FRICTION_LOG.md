# SHARMAN — Amazon Developer Hackathon Friction Log

## 1. Ring Developer Playground simulated events

**Task attempted:**
Integrate Ring Motion, Package, and Vehicle events into SHARMAN's permission-aware Home runtime.

**Steps taken:**

1. Opened the official Ring Developer Playground.
2. Discovered the simulated Ring device through the Device List API.
3. Triggered Motion, Package, and Vehicle simulations.
4. Queried Device Status and Event History through the official Ring API.
5. Compared the returned records with Ring's documented real-time event structures.

**Expected result:**
The Playground would expose the exact Motion, Package, or Vehicle event payload generated by the simulation.

**Actual result:**
The simulation primarily created live-view activity. Event History returned `event_type: on_demand`, representing a live-view session rather than exposing the original Motion, Package, or Vehicle trigger as an equivalent event payload.

**Severity:** Important

**Workaround:**
SHARMAN preserves `on_demand` as neutral session metadata instead of incorrectly treating it as motion or visitor detection. Real-time Motion, Package, Vehicle, and doorbell structures were implemented using the official Ring documentation, while live Ring API validation was performed separately for device discovery, device status, and Event History.

**Actionable suggestion:**
Add an event-debug panel to the Ring Developer Playground that displays the exact generated real-time event payload, including event type, subtype, device ID, timestamp, and webhook-equivalent JSON.

## 2. Ring Playground temporary credentials

**Task attempted:**
Repeatedly validate SHARMAN against the live Ring Developer Playground API.

**Steps taken:**
Generated a Playground access token, supplied it to SHARMAN through runtime environment configuration, and executed live API validation for device discovery, status, and history.

**Expected result:**
A development session long enough to support repeated integration testing.

**Actual result:**
The temporary Playground credential expired during longer development and validation sessions, requiring regeneration.

**Severity:** Minor

**Workaround:**
SHARMAN loads the credential only from a runtime environment variable. Tokens are never stored in source code, the frontend, fixtures, or QA evidence and are removed after validation.

**Actionable suggestion:**
Display the remaining token lifetime prominently in the Playground and provide a streamlined one-click regeneration flow.

## 3. Amazon Bedrock / Nova configuration

**Task attempted:**
Integrate Amazon Nova 2 Lite through Amazon Bedrock's Converse API for permission-decision explanations.

**Steps taken:**
Configured the AWS profile and region, selected the Nova inference profile, tested the AWS SDK directly, and then validated SHARMAN's REST and MCP integration.

**Expected result:**
Select a Nova model and invoke it through the Converse API.

**Actual result:**
Determining the correct region, model/inference-profile identifier, and configuration required additional investigation before end-to-end inference succeeded.

**Severity:** Minor

**Workaround:**
SHARMAN uses explicit runtime configuration and validates Bedrock output before displaying it. If Bedrock is unavailable or produces invalid output, SHARMAN falls back to a deterministic local explanation without changing the original permission result.

**Actionable suggestion:**
Provide more end-to-end examples showing Nova inference-profile configuration with the Converse API, including regional and global inference-profile examples.

---

## Result

None of these issues blocked SHARMAN.

The final implementation successfully live-validated:

- Official Ring Developer Playground device discovery
- Ring device status
- Ring Event History
- Amazon Bedrock / Nova inference
- Real Streamable HTTP MCP integration

Ring API and Bedrock validation were performed locally. Live Ring Motion webhook receipt, physical Ring hardware, and Alexa+ speech were not verified; Alexa+ speech remains simulated.

The friction encountered also influenced an important SHARMAN design principle: external data is never given semantics that its source does not actually provide.
